## Mechanism

In cached mode `num_notify_warps = 0` (dispatch.hpp:251), so `kQPStartIdx = 0` (qp_mapping.cuh:78) and the data channels are spread over QP 0..10. With 28 SMs > 11 QPs, channels 0..17 land on QP 0 with per-part signal ids 0..17 (kNumParts = 1). The rail barrier (`gin_barrier_wo_local_sync`, run only by block 0) uses QP 0 signal ids 0..num_rdma_ranks-2 = 0..2. Channels 0..2 therefore share a GIN counter with the barrier: a fast peer's data increment satisfies the barrier slot, the real barrier increment then counts as data (landed = expected + 1), and the forward warp TMA-forwards a token whose payload has not landed (SRD may deliver the in-band header first). A garbage destination rank/slot gives the wild write (Xid 13/31); a valid-but-wrong one silently corrupts gradients (Inf/NaN).

The probe arm observed it directly: `data_overcount` / `foreign_increment` fire only on channels 1 and 2, always exactly +1, and `stale_payload` caught corrupted payloads (two would have been wild writes, one a silent wrong forward); that run then aborted with `found Inf in local grad norm for bucket #0 in backward pass before data-parallel communication collective` on all 32 ranks of the EP group -- the same bug can surface as an Inf/NaN gradient instead of an Xid.
